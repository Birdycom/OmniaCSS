Border-color

CSS class _borders_outlines.scss borders-color.html v0.2.0

Border color sets the colour of the border. Use .border-transparent for an invisible border that still reserves space, or .border-current to match the element’s text color. The full Omnia and HTML palette is available as .border-{name}-{step} (e.g. .border-dodgerblue-50); RAL colors as .border-{name}. See Colors for the full palette. Neutrals from $bordercolors; palette classes are generated in _borders_outlines.scss.

What it does: border-color sets the color of the border; the border only shows when it has a style and a width (use .border-solid plus a width class). Per side variants exist in the Sides & Images page. When to use: cards, inputs, dividers, state colors (error, success). Gotchas: without a style the border is invisible even with a color; the default color is currentcolor, so a border inherits the text color; and transparent borders still take space (handy to avoid layout shift between states). The -mix-* classes blend the palette color with transparency. See MDN: border-color.

All classes set border-color. Neutrals: .border-transparent, .border-current. Palette: .border-{name}-{step} (Omnia/HTML) and .border-{name} (RAL). Same naming as on the Colors page.

Modern color: light-dark() and color-mix()

Border colors take any CSS color, including the newer functions. light-dark(a, b) picks a value per color scheme, so one declaration serves both themes; color-mix(in oklch, a, b) blends two colors (here a palette color with the theme background). Toggle the system theme to see the first card switch. Prefer these over hard-coded colors so a border stays visible in both modes.
