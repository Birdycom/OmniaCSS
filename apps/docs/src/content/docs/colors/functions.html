Color Functions

CSS class _css_functions.scss functions.html v0.8.2

Change the transparency of any Omnia token with alpha() or the relative color syntax (oklch(from … l c h / 50%)), blend tokens with color-mix(), switch between light and dark values with light-dark() and let the browser pick a readable text color with contrast-color(). OmniaCSS adds .bg-current-* and .border-current-* (alpha steps of the text color) and the --color-*-mix-* tokens. Lighter and darker variants come from the tone steps (-2 … -95), so the result stays inside the Omnia palette. See MDN: Relative colors.

Alpha: alpha() and the relative color syntax

The relative syntax takes a color apart into its channels (l c h for OKLCH) and lets you rebuild it, here with a new alpha. alpha(from color / 40%) is the short form that only touches the alpha channel. Both work on var() tokens and on currentColor.

.cf-a50 { background: oklch(from var(--color-vividblue-80) l c h / 0.5); } /* alpha(): only the alpha channel, any color space */ .cf-alpha { background: oklch(from var(--color-magenta-50) l c h / 0.4); /* fallback */ background: alpha(from var(--color-magenta-50) / 40%); } /* Other channel tricks (code only — prefer Omnia tone steps for real UI) */ .muted { color: oklch(from currentColor l c h / 0.6); } .no-tint { color: oklch(from var(--color-blue-50) l 0 h); } /* grayscale */ .swap { color: rgb(from var(--color-red-50) b g r); } /* swap channels */

color-mix() and interpolation spaces

color-mix(in <space>, a p%, b) blends two colors. The color space decides the path: sRGB goes through gray, OKLab stays bright, OKLCH keeps chroma and can take the long way around the hue wheel. The same in <space> works inside gradients.

in srgb
in oklab
in oklch
in oklch longer hue
.cf-oklch { background: linear-gradient(90deg in oklch, var(--color-blue-50), var(--color-yellow-50)); } .cf-longer { background: linear-gradient(90deg in oklch longer hue, var(--color-blue-50), var(--color-yellow-50)); } .hover-tint { background: color-mix(in oklch, var(--color-blue-50) 85%, var(--color-black-50)); } .three-way { background: color-mix(in oklch, var(--color-red-50), var(--color-blue-50), var(--color-yellow-50)); }

light-dark(): one declaration for both themes

light-dark(a, b) picks a or b from the element's color-scheme. All --oc-* theme tokens are built this way, so components follow the site theme automatically. Below, the same CSS is shown under a forced light and dark scheme.

color-scheme: lightBackground, border and text come from light-dark().
color-scheme: darkBackground, border and text come from light-dark().
.cf-scheme { background: light-dark(var(--color-white-2), var(--color-black-40)); color: light-dark(var(--color-black-40), var(--color-white-60)); border: 1px solid light-dark(var(--color-mistblue-20), var(--color-black-20)); } :root { color-scheme: light dark; } /* follow the system */ .cf-dark { color-scheme: dark; } /* force one area */

contrast-color(): readable text on any background

contrast-color(bg) returns white or black, whichever contrasts most. Keep a fixed color before it for browsers without support.

Color spaces

OmniaCSS writes its tokens in OKLCH by default ($DEFAULT-COLOR-TYPE-VALUE on Color system); all of these spaces are valid input and output.

FunctionChannels
rgb(), #hexred green blue (sRGB)
hsl(), hwb()hue saturation lightness / hue whiteness blackness (sRGB)
lab(), lch()CIE lightness + a/b or chroma/hue
oklab(), oklch()Perceptual lightness + a/b or chroma/hue (OmniaCSS default)
color(display-p3 r g b), color(rec2020 …), color(xyz …)Wide-gamut and reference spaces
currentColor, transparent, system colors (Canvas, AccentColor …)Keywords

Browser support

Relative colors, color-mix(), light-dark() and OKLCH work in all current browsers. alpha() and contrast-color() are new: write a fallback first.
