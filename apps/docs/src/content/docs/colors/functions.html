Color Functions

CSS class _css_functions.scss functions.html v0.8.2

Change the transparency of any Omnia token with alpha() or the relative color syntax (oklch(… / 50%)), blend tokens with color-mix(), switch between light and dark values with light-dark() and let the browser pick a readable text color with contrast-color(). OmniaCSS adds .bg-current-* and .border-current-* (alpha steps of the text color) and the --color-*-mix-* tokens. Lighter and darker variants come from the tone steps (-2 … -95), so the result stays inside the Omnia palette. See MDN: Relative colors.

Alpha: alpha() and the relative color syntax

The relative syntax takes a color apart into its channels (l c h for OKLCH) and lets you rebuild it, here with a new alpha. alpha(from color / 40%) is the short form that only touches the alpha channel. Both work on var() tokens and on currentColor.

oklch(… / 1)
The full color, nothing shows through.
oklch(… / 0.75)
75% opaque: the checkerboard shows through a little.
oklch(… / 0.5)
Half see-through.
oklch(… / 0.25)
Mostly see-through.
alpha(…, 40%)
The alpha() helper: the same color at 40%.
<style> /* the same color with less and less alpha; relative color syntax keeps l, c and h */ .a100 { background: var(--color-vividblue-80); } .a75 { background: oklch(from var(--color-vividblue-80) l c h / 0.75); } .a50 { background: oklch(from var(--color-vividblue-80) l c h / 0.5); } .a25 { background: oklch(from var(--color-vividblue-80) l c h / 0.25); } /* alpha(): only the alpha channel, any color space (with a fallback first) */ .a40 { background: oklch(from var(--color-magenta-50) l c h / 0.4); background: alpha(from var(--color-magenta-50) / 40%); } </style> <div class="a100"></div> <div class="a75"></div> <div class="a50"></div> <div class="a25"></div> <div class="a40"></div> <!-- each box sits on a checkerboard so you see what shows through -->

color-mix() and interpolation spaces

color-mix(in <space>, a p%, b) blends two colors. The color space decides the path: sRGB goes through gray, OKLab stays bright, OKLCH keeps chroma and can take the long way around the hue wheel. The same in <space> works inside gradients.

in srgb
Through a dull grey in the middle.
in oklab
A cleaner path, still a little grey in the middle.
in oklch
Through vivid green: the hue takes the short way.
in oklch longer hue
The long way round the color wheel: through purple, red and orange.
<style> .srgb { background: linear-gradient(90deg in srgb, var(--color-blue-50), var(--color-yellow-50)); } .oklab { background: linear-gradient(90deg in oklab, var(--color-blue-50), var(--color-yellow-50)); } .oklch { background: linear-gradient(90deg in oklch, var(--color-blue-50), var(--color-yellow-50)); } .longer { background: linear-gradient(90deg in oklch longer hue, var(--color-blue-50), var(--color-yellow-50)); } </style> <div class="srgb"></div> <div class="oklab"></div> <div class="oklch"></div> <div class="longer"></div> <style> /* the same idea works in color-mix() */ .hover-tint { background: color-mix(in oklch, var(--color-blue-50) 85%, var(--color-black-50)); } </style>

light-dark(): one declaration for both themes

light-dark(a, b) picks a or b from the element's color-scheme. All --oc-* theme tokens are built this way, so components follow the site theme automatically. Below, the same CSS is shown under a forced light and dark scheme.

color-scheme: light
light-dark() picks the first value of each pair.
color-scheme: lightBackground, border, text and button color all come from light-dark().
color-scheme: dark
light-dark() picks the second value of each pair.
color-scheme: darkBackground, border, text and button color all come from light-dark().
.cf-scheme { background: light-dark(var(--color-white-2), var(--color-black-40)); color: light-dark(var(--color-black-40), var(--color-white-60)); border: 1px solid light-dark(var(--color-mistblue-20), var(--color-black-20)); } .cf-scheme button { background: light-dark(var(--color-vividblue-90), var(--color-vividblue-40)); color: light-dark(var(--color-white-50), var(--color-black-50)); } :root { color-scheme: light dark; } /* follow the system */ .cf-dark { color-scheme: dark; } /* force one area */

text-contrast-*: the same as a class v0.18.0

Put text-contrast-yellow-50 next to bg-yellow-50 and the text is black or white, whichever reads best on that color. There is one for every Omnia color and step (text-contrast-red, text-contrast-red-2 … text-contrast-red-95); RAL and HTML colors are left out to keep the stylesheet small. The class carries its own fallback: black or white, computed at build time with the WCAG formula, so older browsers show the same result. For any other background, set --oc-contrast-bg and use text-contrast; without that variable it reads the page background (--oc-background), and older browsers use --oc-contrast-fallback or the normal text color.

Color spaces

OmniaCSS writes its tokens in OKLCH by default ($DEFAULT-COLOR-TYPE-VALUE on Color system); all of these spaces are valid input and output.

FunctionChannels
rgb(), #hexred green blue (sRGB)
hsl(), hwb()hue saturation lightness / hue whiteness blackness (sRGB)
lab(), lch()CIE lightness + a/b or chroma/hue
oklab(), oklch()Perceptual lightness + a/b or chroma/hue (OmniaCSS default)
color(display-p3 r g b), color(rec2020 …), color(xyz …)Wide-gamut and reference spaces
currentColor, transparent, system colors (Canvas, AccentColor …)Keywords

Browser support

Relative colors, color-mix(), light-dark() and OKLCH work in all current browsers. alpha() and contrast-color() are new: write a fallback first.
