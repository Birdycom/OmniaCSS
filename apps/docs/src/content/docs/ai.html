AI assistants (MCP)

The OmniaCSS MCP server lets Claude, Cursor, VS Code Copilot, Windsurf and other AI assistants check OmniaCSS classes before they write them. Without it they guess from Tailwind, and many names and values differ.

@birdycom/omniacss-mcp on npm Source

Why an MCP server

The Model Context Protocol lets an assistant call tools while it works. This server gives it the real OmniaCSS class index.

  • No guessed classes. The assistant looks up each class it is unsure of and gets the exact CSS, or the closest correct name for a typo (felx → flex, hovr: → hover:).
  • The OmniaCSS scale, not Tailwind's. In OmniaCSS p-1 is 1rem and p-4 is 4rem. The server shows the value of every class.
  • Real OmniaUI components. Instead of writing a modal or a pricing section from scratch, the assistant takes the reference markup of the OmniaUI component or block, and the command that adds it as HTML, React, Vue or Blade.
  • Read-only and local. The server runs on your computer and never changes a file. Only read_docs goes on the network, and only to omniacss.eu and omniaui.eu.
  • The same index as the editor. The class index is the one the editor extension uses. When your project has its own OmniaUI packages installed, those versions are used. OmniaUI Pro blocks are listed by name; their markup appears only when @birdycom/omniaui-pro is installed.

Install @birdycom/omniacss-mcp

Free, MIT licensed, same version number as @birdycom/omniacss. Needs Node.js 22 or newer; npx downloads it, so there is nothing to install first.

Claude Code

claude mcp add omniacss -- npx -y @birdycom/omniacss-mcp

Cursor, Claude Desktop, Windsurf

Add the server to .cursor/mcp.json (Cursor), claude_desktop_config.json (Claude Desktop) or ~/.codeium/windsurf/mcp_config.json (Windsurf):

{ "mcpServers": { "omniacss": { "command": "npx", "args": ["-y", "@birdycom/omniacss-mcp"] } } }

VS Code (Copilot)

// .vscode/mcp.json { "servers": { "omniacss": { "type": "stdio", "command": "npx", "args": ["-y", "@birdycom/omniacss-mcp"] } } }

Start the server in your project folder (most clients do that by default), so the OmniaUI packages installed there are found. To keep it on your OmniaCSS version, add the version to the name: @birdycom/omniacss-mcp@0.12.

Tools

The assistant picks these itself. The server also sends a short guide on connecting, so the assistant knows the OmniaCSS rules before its first call.

ToolWhat it does
getting_startedInstall (CDN, npm with PostCSS or Vite, CLI), dark mode and the rules for writing OmniaCSS markup
lookup_classesChecks classes, variants included (md:hover:…), and OmniaUI oc-* classes. Returns the exact CSS, or the closest correct name
search_utilitiesFinds classes by name or by CSS: anchor, grid cols, position-area
list_variantsLists every variant prefix, or shows the selector or at-rule that one variant produces
color_tokensLists the theme tokens (--oc-primary …) with their light and dark colors, and the palette colors with their hex value
convert_tailwindGives the native OmniaCSS class for a Tailwind class (bg-blue-500 → bg-vividblue-80), or the CSS that the migrate plugin generates for it
list_componentsFinds OmniaUI components (modal, tabs …) and blocks (pricing, hero, dashboard …) by name or description
get_componentThe reference HTML of one component or block, the packages it needs, and npx omniaui add for HTML, React, Vue or Blade
search_docs, read_docsFind pages and sections of the OmniaCSS and OmniaUI docs, and read one as text with its code examples

In practice

Ask for a component and tell the assistant to use the tools:

Build a pricing card with OmniaCSS, two columns from cq-md up. Check every class with the omniacss tools before you use it.

This is what lookup_classes returns for one class:

{ "token": "cq-md:grid-cols-2", "known": true, "kind": "utility", "css": "@container (min-width: 28rem) {\n .cq-md\\:grid-cols-2 {\n grid-template-columns: repeat(2, minmax(0, 1fr));\n }\n}" }

Moving a Tailwind project? Let the assistant run convert_tailwind on the classes, or use @birdycom/omniacss-migrate for the whole project.

In your own code

The same lookups without MCP, for scripts and build checks.

import { load } from "@birdycom/omniacss-mcp/knowledge"; const kb = await load(); kb.lookup(["p-1", "md:flx"]); // [{ token: "p-1", known: true, css: ".p-1 { padding: 1rem; … }" }, // { token: "md:flx", known: false, hint: 'Unknown utility "flx", did you mean "md:flex"?' }]
