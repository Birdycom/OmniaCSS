Install via npm or CDN

npm install -D @birdycom/omniacss-cli npx omniacss init <!-- jsDelivr (unpkg works the same: https://unpkg.com/@birdycom/...) --> <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@birdycom/omniacss@0.12.1/dist/omnia.starter.min.css"> <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@birdycom/omniaui@0.12.1/dist/components.min.css"> <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@birdycom/omniaui-blocks@0.12.1/dist/blocks.min.css">

Prototyping: the CDN starter bundle (omnia.starter.min.css, about 96 KB, 15 KB gzip) covers the most used utilities: reset, layout (display, flex, grid, position, overflow), spacing, sizing, typography, borders, radius, shadows, transitions, container-query variants (cq-xs: to cq-xl:) and the Omnia colors with hover:/focus: states. Components and blocks add about 116 KB (20 KB gzip).

Production: run npx @birdycom/omniacss-cli build to generate only the CSS you use. The full utility build (@birdycom/omniacss/min, about 9 MB) is meant for tooling, not for a CDN link.

Color tokens in your own CSS

The build keeps only the tokens your project uses. Where it looks for them:

  • Your markup (the content globs): classes and any var(--color-…) you write there.
  • The stylesheet with @omnia;: tokens you use in the same file are kept automatically (since 0.12.1).
  • Other CSS files of your own (for example resources/css/scene.css): add them to content, so their var(--color-…) tokens stay in the build.
// omnia.config.json { "content": ["resources/views/**/*.blade.php", "resources/js/**/*.{js,vue}", "resources/css/**/*.css"] }

With the PostCSS plugin you can also hand over the text of other stylesheets: omniacss({ content, referencedBy: [cssText] }).

OmniaUI components with PostCSS (@omniaui;)

since 0.12.3

Next to @omnia; the same plugin replaces @omniaui; with the CSS of the OmniaUI components your markup uses, pruned the same way as the utilities. It reads the installed packages: @birdycom/omniaui, -blocks and -pro.

/* resources/css/app.css */ @omniaui; /* every installed OmniaUI package */ @omnia;
  • One package only: @omniaui components;, or @omniaui components blocks;. A named package that is not installed gives a build warning.
  • Layers: the components land in @layer omniaui, the utilities in @layer omnia, and the plugin declares @layer omniaui, omnia;, so a utility class on a component wins. Other names: omniacss({ content, layer: "utilities", omniauiLayer: "components" }); false leaves the CSS outside a layer.
  • Tokens: the palette colors that the component tokens use (--oc-primary → --color-…) stay in the utilities build.

The CLI (omniacss build) already includes the installed OmniaUI CSS; --no-components turns that off.

OmniaUI CLI: add components in your framework

Components and blocks live in OmniaUI, with its own CLI omniaui (in @birdycom/omniaui). omniacss add only points you there. Every component and block exists in four flavours: css (HTML snippet), vue, react and blade. omniaui add copies the source into your project so you own the code; omniaui list shows what is available per flavour.

npx omniaui add button modal # flavour is detected npx omniaui add accordion -f vue # Vue: OcAccordion.vue + OcAccordionItem.vue + composables npx omniaui add modal -f react --dir src/ui # React: Modal.tsx + Button.tsx + hooks.tsx + utils.ts npx omniaui add hero --kind block -f blade # Blade: block/hero.blade.php npx omniaui add card -f vue --import # only print the import for the npm package npx omniaui add button --dry-run # show what would be copied npx omniaui list -f vue --kind block # names available in that flavour
  • Detection: framework in omnia.config.json (written by init), else package.json (vue or nuxt gives vue, react or next gives react), else Laravel (artisan or composer.json) gives blade, else css. -f/--framework always wins.
  • Target folder (--dir): vue and react use resources/js/components/oc in Laravel projects and src/components/oc elsewhere (components/, blocks/, composables/ keep their layout so imports stay valid); css uses resources/views/oc-snippets or oc-snippets; blade uses resources/views/components/oc and rewrites <x-oc::button> to <x-oc.button>.
  • Dependencies (sub-parts, hooks, utils, composables, nested Blade components) are copied with the component. Existing files are skipped unless you pass --force.
  • Sources: read from the installed package. If it is missing, the CLI tells you what to install: npm i @birdycom/omniaui-vue, npm i @birdycom/omniaui-react or composer require birdycom/omniaui-laravel.
  • The styles always come from @birdycom/omniaui and @birdycom/omniaui-blocks; the new folder is added to the content globs in omnia.config.json.

See Vue, React and Laravel for the framework packages.
