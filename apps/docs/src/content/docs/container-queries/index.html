Container Queries

CSS class _containment.scss container-queries/index.html v0.3.0

Container queries style elements based on the size of their container instead of the viewport. Turn an element into a query container with .container-inline-size (or the short alias .cq-inline), then use the .cq-{xs|sm|md|lg|xl}: variants on its children. Containment and content-visibility isolate rendering work for better performance. See MDN: Container queries.

Container query variants

Same idea as the responsive sm:/md:/lg: prefixes, but measured against the nearest query container. Available for block, hidden, flex, grid, inline-flex, flex-row, flex-col and grid-cols-1 … grid-cols-6.

ClassCSS
.cq-xs:{utility}@container (min-width: 20rem)
.cq-sm:{utility}@container (min-width: 24rem)
.cq-md:{utility}@container (min-width: 28rem)
.cq-lg:{utility}@container (min-width: 32rem)
.cq-xl:{utility}@container (min-width: 36rem)

What it does: a container query applies styles based on the width of a parent (the query container) rather than the viewport, so a component adapts to wherever you place it: a wide main column, a narrow sidebar or a modal. When to use: reusable cards, widgets and form rows. Use the viewport prefixes (md:) for page-level layout and cq-*: for component-level layout. Gotchas: an element cannot query itself, only an ancestor; inline-size containment means the container no longer sizes itself from its children (give it a width); and a child never reacts to a container that is not container-type. See MDN: container queries.

Container query units: cqi, cqb, cqw

1cqi is 1% of the container's inline size (cqb block size, cqmin/cqmax the smaller/larger). They let type and spacing scale with the component, not the viewport. Without a container they fall back to the small viewport units. Drag the handle: the heading and padding scale smoothly.

Named containers

With .cq-name-* a rule can target one specific ancestor. Below, the inner card sits in a small box inside a resizable sidebar container, but @container sidebar (min-width: 26rem) skips the nearest container and reacts to the sidebar. The card turns green when the sidebar is wide, no matter how small the card itself is.

I follow the sidebar, not my parent
<aside class="cq-inline cq-name-sidebar"> <div class="cq-inline cq-name-card"><div class="note">…</div></div> </aside> @container sidebar (min-width: 26rem) { .note { background: green; } }

Style queries

@container style(--tone: warn) queries the computed value of a custom property on a parent, so a component can change look from a single data attribute or token set by its parent, without extra classes. The custom property does not need any container-type. Gotcha: only custom properties are supported cross-browser (Chrome, Edge, Safari 18+); Firefox does not support style queries yet, so the base style must still look acceptable. See MDN: style queries.

--tone: info
--tone: warn
--tone: ok
<div style="--tone: warn"><div class="tone">…</div></div> @container style(--tone: warn) { .tone { background: orange; } }

Scroll-state container: stuck

Usage example

For queries the variants do not cover, write your own @container rule against a named container.

<aside class="cq-inline cq-name-sidebar"> <div class="card">…</div> </aside> /* In your CSS */ @container sidebar (min-width: 400px) { .card { flex-direction: row; } } /* Scroll-state query: style a sticky header once it is stuck */ .header { position: sticky; top: 0; } @container scroll-state(stuck: top) { .header > nav { box-shadow: 0 2px 8px rgb(0 0 0 / 0.15); } }

Browser support

Size container queries degrade gracefully: without support the base (mobile-first) classes stay active. Scroll-state queries are newer and are simply ignored by browsers that lack them.
