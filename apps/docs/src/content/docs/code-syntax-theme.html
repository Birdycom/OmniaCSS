From VS Code theme to code-syntax CSS

CSS oc-code-syntax.css v0.2.0

How the colors of the VS Code theme (Birdycom Omnia Dark) end up in the CSS for code blocks. One shared set of variables serves HTML, CSS, PHP, JS, JSON and Python. The technical reference (files, script, token variables) is on Code syntax.

Starting point

The theme src/json/omniathememain.json holds colors (the editor UI) and tokenColors (scope → foreground / fontStyle). The syntax CSS (oc-code-syntax.css) colors classes such as .hl-tag, .hl-attr and .hl-string; the docs highlighter (apps/docs/src/lib/highlight.mjs) adds those spans during the build. The goal: code blocks on the site in the same colors as in the editor, with one theme CSS file for every language.

Overview per language (theme → CSS)

One set of CSS custom properties: the conversion script reads the theme JSON and fills --oc-syntax-*. That way one file works for HTML, PHP, JS and the rest.

How the CSS is made

A build script does it: oc-code-syntax.css holds all token classes and the Omnia Dark theme variables in one file. The script reads src/json/omniathememain.json, finds the right tokenColors or colors entry for each token type, and updates the :root block in oc-code-syntax.css.

The command (npm run code-syntax-theme) and where the script lives: Code syntax → Theme generation.

Other languages (for example PHP)

The same CSS file serves every code block. For PHP or JS a highlighter must turn the source into HTML with the same classes (.hl-keyword, .hl-string, .hl-variable and so on), for example Prism or Highlight.js with a custom theme, or an extension of apps/docs/src/lib/highlight.mjs. The overview per language on this page is the reference for which theme scope belongs to which token type.
