View Transitions

CSS class _view_transitions.scss view-transitions/index.html v0.3.0

Animate between two states of a page (same-document, via document.startViewTransition()) or between pages (cross-document). Give elements a .vt-name-* so the browser morphs them, and group them with .vt-class-* to share an animation. Animations are disabled automatically for prefers-reduced-motion. See MDN: View Transition API.

View transition name

Every name must be unique on the page at the moment of the transition. match-element lets the browser generate a unique name per element (lists). What: the browser takes a snapshot of every named element before and after the DOM change and morphs position, size and content between the two. When: reordering a list, opening a card into a detail view, toggling a layout, swapping a theme. Gotchas: two elements with the same name make the whole transition fail (it is skipped silently), so use .vt-name-match-element for repeated items; named elements get their own stacking context; and the page is non-interactive while the animation runs. More: MDN: view-transition-name.

View transition class

Applies a shared animation to all named elements with the same class. fade shortens the cross-fade to 200ms; slide slides old content out and new content in. What: a class is to view transitions what a CSS class is to elements: one rule such as ::view-transition-old(*.slide) styles every named element carrying view-transition-class: slide. When: many named elements (list items, cards) that should share one animation. Gotcha: the class only targets the pseudo-elements, it does not make the element unique: it still needs a view-transition-name. More: MDN: view-transition-class.

Cross-document opt-in

Multi-page sites opt in with the global @view-transition at-rule. OmniaCSS does not emit it by default; include the mixin in your own stylesheet. When: classic server-rendered sites that want smooth navigation without a client-side router. Gotchas: both pages must opt in, be same-origin and load quickly (a slow navigation skips the transition); named elements match across pages by view-transition-name. More: MDN: @view-transition.

Pseudo-elements

Style the transition itself with these pseudo-elements. *.slide targets every group with view-transition-class: slide. What: during a transition the browser builds a tree (::view-transition > group > image-pair > old + new) above the page; each layer can be animated with normal CSS animations. Gotcha: old and new are replaced images that already cross-fade by default (mix-blend-mode: plus-lighter); set height: 100% on them when the size changes and you want the content to stretch. More: MDN: Using the View Transition API.

Browser support

Without support the DOM update happens instantly, without animation — view transitions are a progressive enhancement.
