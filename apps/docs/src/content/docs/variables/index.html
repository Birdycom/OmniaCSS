Variables (Custom Properties)

CSS feature _colors_tokens.scss variables/index.html v0.8.2

Custom properties (--name: value, read with var(--name, fallback)) inherit through the DOM, can be changed per element, per state or per media query, and are live: change one and everything that uses it updates. All OmniaCSS colors are variables (--color-{name}-{step}), the theme is built on --oc-* tokens, and several utilities read a variable you can override (--oc-stagger, --oc-fan). See MDN: Using CSS custom properties.

OmniaCSS variables

--color-{name}-{2…95|100}Omnia, HTML palette tone (OKLCH); -100 is the base color

--oc-staggerStep for .delay-stagger (default 60ms)
--oc-fanAngle for .fan (default 6deg)

Scope, inheritance and fallback

A variable set on an element applies to that element and all its descendants. var(--x, fallback) uses the fallback when --x is not set. The same card component below gets three looks from one inline variable.

--va-accent: (not set)
No variable is set, so the border and button fall back to grey.
DefaultNo variable: fallback colors.
--va-accent: vividblue-90
The same card, with the variable set inline to blue.
Blue--va-accent set inline.
--va-accent: magenta-90
Another value, another color. The CSS of the card stays the same.
MagentaSame component, another value.

@property: typed variables you can animate

An unregistered variable is just text and jumps from value to value. Register it with @property and the browser can interpolate it: an integer becomes a counter, a color becomes a gradient you can transition.

@property --va-num (integer)
Hover the box: the number counts up to 2500 instead of jumping there.
hover me
@property --va-from (color)
Hover the box: the start color of the gradient fades to orange.
hover me
<div class="va-count-wrap"><span class="va-counter"></span><small>hover me</small></div> <div class="va-grad">hover me</div> @property --va-num { syntax: "<integer>"; inherits: false; initial-value: 0; } .va-counter { counter-reset: va var(--va-num); transition: --va-num 2s ease-out; } .va-counter::after { content: counter(va) "+"; } .va-count-wrap:hover .va-counter { --va-num: 2500; } @property --va-from { syntax: "<color>"; inherits: false; initial-value: transparent; } .va-grad { --va-from: var(--color-vividblue-90); background: linear-gradient(135deg, var(--va-from), var(--color-magenta-90)); transition: --va-from 0.6s; } .va-grad:hover { --va-from: var(--color-orange-95); }

Variables in OmniaCSS utilities

Utilities that read a variable can be tuned without new classes: set it inline, on a parent, or in a state.

.fan + style="--oc-fan: 12deg"
The .fan class reads --oc-fan. Set inline on the hand, every card turns 12deg further than its neighbour (the default is 6deg).
.delay-stagger + style="--oc-stagger: 250ms"
Hover the list: with a step of 250ms the items move one by one, slow enough to follow.

Advanced: the space toggle

A variable set to a single space is valid but empty; set to initial it is "guaranteed invalid", so var() falls back. That makes an on/off switch inside a single value.

--va-on: ;
A single space is a valid, empty value, so the green background applies.
On: green background
--va-on: initial
Invalid on purpose: var() fails, so the background falls back to none.
Off: no background
<span class="va-toggle">On: green background</span> <span class="va-toggle is-off">Off: no background</span> .va-toggle { --va-on: ; background: var(--va-on) var(--color-forestgreen-60); color: var(--va-on) var(--color-white-50); } .va-toggle.is-off { --va-on: initial; } /* var() invalid → background falls back to its initial value */

Browser support

Custom properties and var() work everywhere. @property is in all current browsers; style queries on variables are new in Firefox.
