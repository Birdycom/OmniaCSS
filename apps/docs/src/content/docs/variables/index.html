Variables (Custom Properties)

CSS feature _colors_tokens.scss variables/index.html v0.8.2

Custom properties (--name: value, read with var(--name, fallback)) inherit through the DOM, can be changed per element, per state or per media query, and are live: change one and everything that uses it updates. All OmniaCSS colors are variables (--color-{name}-{step}), the theme is built on --oc-* tokens, and several utilities read a variable you can override (--oc-stagger, --oc-fan). See MDN: Using CSS custom properties.

Scope, inheritance and fallback

A variable set on an element applies to that element and all its descendants. var(--x, fallback) uses the fallback when --x is not set. The same card component below gets three looks from one inline variable.

DefaultNo variable: fallback colors.
Blue--va-accent set inline.
MagentaSame component.
.va-card { border: 2px solid var(--va-accent, var(--oc-border)); } .va-card strong { color: var(--va-accent, var(--oc-foreground)); } .va-card button { background: var(--va-accent, var(--color-gray-50)); } /* <div class="va-card" style="--va-accent: var(--color-magenta-50)"> … </div> */

Theming with :has() and one variable

The radio buttons set --va-brand on the whole panel through :has(). The background, button and bar all derive from it with color-mix(). No JavaScript.

.va-theme { --va-brand: var(--color-vividblue-80); background: color-mix(in oklch, var(--va-brand) 10%, var(--oc-card)); } .va-theme:has(input[value="magenta"]:checked) { --va-brand: var(--color-magenta-50); } .va-theme:has(input[value="green"]:checked) { --va-brand: var(--color-green-50); } .va-btn { background: var(--va-brand); } .va-bar { background: linear-gradient(90deg, var(--va-brand), color-mix(in oklch, var(--va-brand), var(--oc-card) 60%)); }

@property: typed variables you can animate

An unregistered variable is just text and jumps from value to value. Register it with @property and the browser can interpolate it: an integer becomes a counter, a color becomes a gradient you can transition.

hover me
hover me
@property --va-num { syntax: "<integer>"; inherits: false; initial-value: 0; } .va-counter { counter-reset: va var(--va-num); transition: --va-num 2s ease-out; } .va-counter::after { content: counter(va) "+"; } .va-count-wrap:hover .va-counter { --va-num: 2500; } @property --va-from { syntax: "<color>"; inherits: false; initial-value: transparent; } .va-grad { --va-from: var(--color-blue-50); background: linear-gradient(135deg, var(--va-from), var(--color-magenta-50)); transition: --va-from 0.6s; } .va-grad:hover { --va-from: var(--color-orange-50); }

Variables in OmniaCSS utilities

Utilities that read a variable can be tuned without new classes: set it inline, on a parent, or in a state.

<ul class="group" style="--oc-stagger: 80ms"> <li class="delay-stagger …">…</li> </ul> <div class="fan" style="--oc-fan: 12deg"></div> <div style="--status: danger"> … </div> <!-- read by @container style(--status: danger) -->

Advanced: the space toggle

A variable set to a single space is valid but empty; set to initial it is "guaranteed invalid", so var() falls back. That makes an on/off switch inside a single value.

--va-on: ␠ (on) --va-on: initial (off)
.va-toggle { --va-on: ; background: var(--va-on) var(--color-green-60); } .va-toggle.is-off { --va-on: initial; } /* var() invalid → background falls back to its initial value */

Browser support

Custom properties and var() work everywhere. @property is in all current browsers; style queries on variables are new in Firefox.
