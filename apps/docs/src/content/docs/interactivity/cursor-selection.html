How the pointer looks and what the user can select or click. All interactivity utilities.

Cursor

What: the mouse pointer shape while hovering an element. When: pointer for custom clickable elements, not-allowed for disabled actions, grab/grabbing for draggable items, wait and progress during loading. Gotchas: real buttons and links already get the right cursor, so add it only to non-semantic elements (and prefer making them real buttons); the cursor is invisible on touch devices. More: MDN: cursor.

User Select

What: whether text can be selected. When: none on UI chrome such as button labels or drag handles, all on values users copy in one click (API keys, IDs). Gotcha: do not disable selection on real content; it hurts accessibility and copy and paste. More: MDN: user-select.

Pointer Events

What: whether an element is a target of mouse and touch events. When: none lets clicks fall through decorative overlays, gradients and disabled-looking items to what is beneath. Gotcha: it does not remove an element from keyboard navigation: a link with pointer-events: none can still be tabbed to and activated, so also use inert or aria-disabled semantics. More: MDN: pointer-events.
