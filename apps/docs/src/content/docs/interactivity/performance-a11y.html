will-change hints and reading order for keyboard and screen reader users. All interactivity utilities.

Will Change

What: a hint that a property is about to change, so the browser can promote the element to its own layer beforehand. Gotchas: every hinted element costs memory, and will-change: transform creates a stacking context and a containing block for fixed children as a side effect; add it right before an animation and remove it after, or only on elements that animate constantly. More: MDN: will-change.

A hint for the browser only - nothing changes visually. Use it sparingly, on elements that are about to animate.

Reading Flow

Makes keyboard focus and screen reader order follow the visual order of a flex or grid layout (e.g. after .order-* or .flex-row-reverse) instead of the DOM order. Gotcha: the DOM order is still the source of truth for browsers without support, so keep it sensible and treat reading-flow as an enhancement. More: MDN: reading-flow.
