Display

_flexbox.scss v0.2.0

Choose how an element generates its box: block-level or inline-level flex and grid containers.

Setting display to flex or grid turns an element into a container: its direct children become flex or grid items. The block-level versions (.flex, .grid) take the full available width, the inline-* versions only as much as their content and sit in the text flow like a word. Only direct children are affected; nested containers need their own class. .contents removes the box itself so its children take part in the parent layout. See MDN: display.

ClassRender Mode
.flexBlock-level flex container
.inline-flexInline-level flex container
.gridBlock-level grid container
.inline-gridInline-level grid container
.blockBlock box (default for div)
.flow-rootBlock box that contains its floats
.contentsBox disappears, children stay

Real use: a status chip in a sentence

A chip with a dot and a word needs flexbox to line them up. With .flex it breaks the sentence; .inline-flex keeps it in the text.

.flex
The chip breaks the sentence and stretches over the full width.
Order 1042 is Paid and leaves the warehouse today.
.inline-flex
The chip is as wide as its content and stays in the sentence.
Order 1042 is Paid and leaves the warehouse today.
<!-- .flex: the chip breaks the sentence --> <p>Order 1042 is <span class="flex align-items-center gap-0.3 chip">Paid</span> and leaves the warehouse today.</p> <!-- .inline-flex: the chip stays in the sentence --> <p>Order 1042 is <span class="inline-flex align-items-center gap-0.3 chip">Paid</span> and leaves the warehouse today.</p> <!-- .chip is your own style: padding, radius, background and a dot (::before) -->

display: contents

Wrapper elements that exist only for markup reasons can be dissolved so their children join the grid of the grandparent. Below: a form where every label and field sit in a wrapper div. Gotcha: older browsers dropped display: contents elements from the accessibility tree; always test buttons and lists.

Without .contents
Each wrapper (blue dashed line) is one grid item, so label and field share one cell and the pairs zigzag over the two columns.
.contents on the wrappers
The wrappers disappear. Labels go into column 1, fields into column 2.
<!-- Without .contents: each wrapper div is one grid item --> <div class="grid gap-0.6" style="grid-template-columns: auto 1fr"> <div><label for="company">Company</label> <input id="company" value="Company 1"></div> <div><label for="email">Email</label> <input id="email" value="info@company1.example"></div> <div><label for="phone">Phone</label> <input id="phone" value="+32 000 00 00 01"></div> </div> <!-- With .contents: labels go into column 1, fields into column 2 --> <div class="grid gap-0.6" style="grid-template-columns: auto 1fr"> <div class="contents"> <label for="company">Company</label> <input id="company" value="Company 1"> </div> <div class="contents"> <label for="email">Email</label> <input id="email" value="info@company1.example"> </div> <div class="contents"> <label for="phone">Phone</label> <input id="phone" value="+32 000 00 00 01"> </div> </div>
