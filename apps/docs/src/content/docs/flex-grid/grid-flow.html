Grid Auto Flow

_grid.scss v0.2.0

Control the auto-placement algorithm for items in a grid using .grid-flow-{type}.

Auto-placement puts every item in the next free cell. row (default) fills rows left to right, col fills columns top to bottom (you then set the number of rows with .grid-rows-n). By default the cursor never moves back, so a wide item that does not fit leaves a hole. dense lets later, smaller items backfill those holes. Gotcha: dense packing changes the visual order but not the DOM order, which hurts keyboard and screen reader users, so avoid it for content that has a meaning in sequence (use it for galleries and tiles). See MDN: grid-auto-flow.

ClassPlacement Algorithm
.grid-flow-rowFill each row in turn (default)
.grid-flow-colFill each column in turn
.grid-flow-denseFill holes in the grid (dense packing)
.grid-flow-row-denseRow-based dense packing
.grid-flow-col-denseCol-based dense packing

Auto Sizing

Control the size of implicitly created grid tracks.

Tracks that you did not define (for example the columns created by .grid-flow-col) are implicit. These classes set grid-auto-columns / grid-auto-rows for them: auto sizes by content and stretches into free space, fr makes equal shares (minmax(0, 1fr)), min / max hug the smallest or largest content. See MDN: grid-auto-columns.

Masonry / grid-lanes (experimental)

A native masonry layout (items packed in lanes without row alignment) is being standardised as display: grid-lanes (earlier drafts: grid-template-rows: masonry). It is available behind a flag or in preview builds only, so there is no OmniaCSS class yet. Use it as progressive enhancement over a normal grid, and check MDN: Masonry layout for the current status.

.gallery { display: grid; grid-template-columns: repeat(auto-fill, minmax(12rem, 1fr)); gap: 1rem; } /* Experimental: only where supported */ @supports (display: grid-lanes) { .gallery { display: grid-lanes; } }
