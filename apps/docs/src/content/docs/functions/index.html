CSS Functions

CSS class _css_functions.scss functions/index.html v0.8.2

CSS can calculate. From calc() via clamp() to progress(), stepped values (round(), mod()), exponents and trigonometry, tree counting (sibling-index(), sibling-count()), typed attr(), inline conditions with if(), calc-size() and random(). OmniaCSS ships utilities on top of them (.delay-stagger, .fan, .text-fluid-*), and you can use every function in your own CSS next to the tokens. Color functions are on Color functions. See MDN: CSS functions.

From clamp() to progress()

clamp(min, value, max) limits a value. progress(value, start, end) goes one step further: it tells you how far a value is between two points, as a number from 0 to 1. Use that number for anything: width, opacity, a color mix, a counter. Below, the width of a dashed box (100cqi), between 10rem and the full width of its stage, gives that number; four panels use it for a bar, a font size, a color and spacing. Drag the bottom-right corner of each box. progress() works in current Chrome, Edge and Firefox; where it is missing, every value sits at its middle (the --p: 0.5 fallback).

Stepped values: round(), mod(), rem()

round(strategy, value, step) snaps to a multiple of step (nearest, up, down, to-zero). The bar below only grows in whole 3rem steps, whatever the container width.

Exponential: pow(), sqrt(), hypot(), log(), exp()

A modular type scale is one formula: 1rem × 1.25step. hypot() gives the diagonal of a box, sqrt() and log() smooth large ranges.

calc(1rem * pow(1.25, var(--step)))
One formula for the whole type scale: each step is 1.25 times the one before, from step -1 to step 5.

if(): conditions inside a value

if() picks a value based on style(), media() or supports(), without a separate rule. Browsers without if() need a plain value. When the if() holds a var(), a plain value on the line above is not enough: those browsers only reject the declaration while they compute the style, and then the background is simply gone. So keep the plain value in the rule and put the if() inside @supports.

calc-size() and interpolate-size: animate to auto

interpolate-size: allow-keywords (utility .interpolate-size-keywords) lets height: auto animate. calc-size(auto, size + 1rem) calculates with intrinsic sizes. Open the accordion: no JavaScript, no max-height trick.

Not in this browser yet. Your browser does not support interpolate-size: the answers open and close at once, without the slide.
::details-content · interpolate-size: allow-keywords
Open a question: the answer slides open to its natural height. No JavaScript, no max-height trick.
How does this open smoothly?

The ::details-content pseudo-element animates its block-size from 0 to auto, because the parent allows keyword interpolation. content-visibility switches with allow-discrete at the end.

Does it work without JavaScript?

Yes. The browser opens and closes the element; the transition is plain CSS on ::details-content.

What happens in older browsers?

The panel opens at once, without the slide. The content is the same, so nothing breaks.

Browser support

calc(), min(), max(), clamp(), the stepped, exponential and trigonometric functions work in every current browser. progress(), sibling-index() and typed attr() are new; if(), calc-size() and random() are not everywhere yet — every demo here writes a fallback first.
