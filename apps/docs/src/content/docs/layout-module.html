Layout Module: Header + Footer

CSS oc-layout-module.css v0.2.0

This module gives one shared header and footer for all pages. It keeps style and behavior the same on home and docs.

Files

  • public/css/oc-layout-module.css (shared styles)
  • apps/docs/src/layouts/ContentPage.astro (header, sidebars and footer rendered at build time — no script)

Required HTML

<link rel="stylesheet" href="../css/oc-layout-module.css"> <body data-ocm-mode="docs" data-ocm-root="../../" data-ocm-active="docs-new" data-ocm-brand-version="v0.1.5" data-ocm-footer-text="OmniaCSS - Inhouse design system documentation"> <div data-ocm-header-slot></div> ... <div data-ocm-footer-slot></div> <!-- header/footer are rendered by the docs build -->

Body data settings

  • data-ocm-mode: home or docs. Docs mode uses fixed header.
  • data-ocm-root: relative base path for nav links (example: ../../).
  • data-ocm-active: active nav id (home, colors, docs-new, ...).
  • data-ocm-brand-version: brand suffix text after dot (default v1).
  • data-ocm-footer-text: custom footer label.

CSS variables you can use

  • --ocm-header-height: header height (default 60px)
  • --ocm-footer-height: footer height (default 36px)
  • --ocm-header-border: border color for header/footer lines
  • --ocm-header-bg: header background color
  • --ocm-footer-bg: footer background color
  • --ocm-text, --ocm-text-soft, --ocm-accent, --ocm-font

Notes

  • For docs layout, use your content wrapper height with calc(100vh - var(--ocm-header-height) - var(--ocm-footer-height)).
  • Keep sidebar/content scroll inside the layout, not on body.
  • Use one module to avoid style drift between pages.
