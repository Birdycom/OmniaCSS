Multi-column Layout

CSS class _layout_flow.scss columns/index.html v0.3.0

Flow content into newspaper-style columns. Use .cols-* for a fixed number of columns or .col-w-* for an ideal column width; the gap utilities (.gap-*) set the space between them. The older .columns-* shorthand classes stay available. See MDN: Multi-column layout.

What it does: multi-column layout flows one block of content into several columns, like a newspaper: the browser decides where each column breaks. When to use: long lists, tag clouds, short articles, link directories. Gotchas: columns balance their height by default (.col-fill-balance), so a fixed-height container fills the first column first only with .col-fill-auto; a heading can span all columns with .col-span-all; and content is read top to bottom per column, which is poor for long text on small screens. Prefer .col-w-* (a minimum width) over a fixed count so the number of columns adapts. See MDN: columns and MDN: column-rule.

OmniaCSS turns modern CSS into utility classes. Multi-column layout flows text from one column into the next, like a newspaper, without any wrapper elements. Combine a column count with a rule between the columns and a gap. The browser balances the columns automatically, and headings can span all columns with .col-span-all. Resize the window to see the text reflow while the number of columns stays the same.

<p class="cols-3 col-rule-solid col-rule-1">…</p>

With .col-w-16 every column is about 16rem wide; the browser decides how many fit. This is responsive without media queries: wide screens get more columns, phones get one. Text keeps a comfortable line length in every situation, which is good for reading long documentation pages.

In a 7rem tall box, .col-fill-balance evens out the column heights; .col-fill-auto fills each column to the full height before starting the next one.

Browser support

Multi-column layout is broadly supported; without support content simply flows in a single column.
