Stacking / Z-Index

_layering.scss v0.2.0

Control the stacking order of elements that overlap.

What: z-index orders overlapping boxes inside a stacking context; higher numbers paint on top. When: dropdowns above content, sticky headers above scrolling rows, overlays above everything. Gotchas: z-index only works on positioned elements (anything but static) and on flex or grid children; a parent that creates a stacking context (position + z-index, opacity < 1, transform, isolation: isolate) traps its children, so .z-50 inside a low parent still loses to a sibling of that parent. Keep a small scale (the 0 to 50 steps here) instead of ever larger numbers. More: MDN: Understanding z-index.

Stacking Demo

Both stacks hold the same three cards in the same code order: A, then B, then C. Without a z-index the card that comes last in the code (C) is on top. With a z-index the highest number wins, so card A with .z-30 comes to the front.

.z-40 works like the other steps. .z-auto is the default: the element paints in code order, as in the left stage below.

When a higher z-index loses

On the left the dark-red card has .z-50 and still lies under the green card with .z-0. The reason: Parent A has .relative .z-10, which makes it a stacking context, so z-50 only counts inside Parent A; the browser first stacks the parents (10 against 20), and everything in Parent B paints above everything in Parent A. On the right Parent A has no z-index, so it is no stacking context and the z-50 card wins.
