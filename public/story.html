    00 Our story April 2022 → today

    From a folder of HTML pages to a framework.

    OmniaCSS started in April 2022 as one developer's set of plain HTML documents with a stylesheet behind them. It stopped, it started again, and it was rebuilt more than once. Below is the documentation page it began with, rebuilt as it looked, and every step from there to the framework of today.

    • First commit · 21 April 2022
    • Rest · 2023 – 2025
    • Restart · February 2026

    01 2022, as it was Sass · PostCSS · px

    A sidebar, an example and the code under it.

    The first documentation was a style guide generated from comments in the Sass source: a sidebar with the sections, and for every class a live example with its code right below. Flat class names, hex colors and pixel values. Click through the sidebar: this is how it looked.

    Colors

    Background and text colors. Every color is a variable in _settings.scss and a class: .bg-{name} and .text-{name}.

    Example
    Code
    <div class="bg-blue text-white p-10">Hello</div>

.bg-blue { background-color: #1976d2; }
.text-white { color: #ffffff; }

    Text colors

    Example

    .text-red .text-green .text-blue .text-gray

    Code
    <p class="text-blue">Customer 1</p>

.text-blue { color: #1976d2; }

    Spacing

    Margin and padding in steps of 5px, from 0 to 50. Sides with -t, -r, -b and -l.

    Example
    .p-10
    .p-20
    Code
    <div class="p-10"><div class="p-20">…</div></div>

.p-10 { padding: 10px; }
.p-20 { padding: 20px; }

    Margin

    Example
    .mb-10
    .mb-10
    .m-auto (width 50%)
    Code
    .mb-10 { margin-bottom: 10px; }
.m-auto { margin: 0 auto; }

    Position

    Position and offsets for badges, overlays and sticky bars.

    02 The steps to now 2022 → today

    Six steps, the same idea.

    The rule has not changed since that first folder: it has to be fast, it has to be CSS, and it has to work. What changed is everything around it.

    1. April 2022

      A folder of HTML documents

      The first commit says it plainly: "Starting to build my CSS framework". A reset, a settings file and a few HTML pages (colors, spacing, position, sizing) to test every class, with Sass and PostCSS behind them. The page above is what that documentation looked like.

    2. May 2022

      The RAL colors

      Color lists in JSON became Sass and then classes: the RAL colors, the HTML named colors and the first Omnia palette. Still rare in a CSS framework. In 2022 a RAL color was a fixed hex value; today it is an OKLCH token you can mix.

    3. 2023 – 2025

      The quiet years

      The documentation generator kept failing on Sass maps (and every color list was a Sass map), and customer work came first. After April 2023 the project rested for almost three years.

    4. February 2026

      The restart

      Modern Sass modules, OKLCH as the color model, the oc- prefix and automatic tests. Version 0.1.0 followed in March, 0.2.0 in April with the first components and the icon catalog. One hex value per color became ten tones per color, each a token.

    5. October 2026

      From 12 MB to a few KB

      npm packages, a CLI and a PostCSS plugin that build only the classes you use. Days later the components, blocks and framework wrappers moved to their own project, OmniaUI, so the CSS core stays small. The editor extension, the migration tool and the AI server followed the same month. The button shows the change best.

    6. Today · v0.17

      CSS first, still

      Modern CSS as utilities, OmniaUI components for HTML, React, Vue and Laravel, starter kits and Pro blocks. Every docs page still shows an example with its code under it, the idea of that first page in 2022.

    03 What stood in the way 3.1 – 3.5

    Five things that slowed it down.

    Tooling3.1

    The Sass compiler of 2022 was deprecated and the documentation theme broke on every Sass update. The restart moved to modern Sass modules and our own docs site, built from the same source as the CSS.

    Size3.2

    Every utility in every color made a 12 MB stylesheet. The answer was an on-demand build: your project gets the classes it uses, a few KB.

    Too much in one place3.3

    Utilities, components, blocks and four frameworks in one package made every change slow. Splitting OmniaCSS and OmniaUI gave each its own pace.

    New CSS, uneven support3.4

    Anchor positioning, scroll-driven animations and :has() do not land in every browser at once. Every docs page shows the support data from MDN, and the demos keep a fallback.

    Time3.5

    Built next to customer projects, by one developer. That is also why it stays small and why everything has a test.
