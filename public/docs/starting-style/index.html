    Entry & Exit Animations

    CSS class _starting_style.scss starting-style/index.html 0 KB JavaScriptNewest CSSv0.3.0

    Animate elements when they appear — popovers, dialogs, newly inserted items — and animate to height: auto, all without JavaScript. .starting-* classes set the state before the first render via @starting-style; combine them with a transition utility such as .transition-all .duration-300. See MDN: @starting-style.

    Starting style

    Initial values the element transitions from when it is first rendered or goes from display: none to visible. What: a normal CSS transition needs a "before" style, but a freshly inserted element has none. @starting-style supplies it, so the element animates to its real style on first render. When: popovers, dialogs, toasts, list items added from JavaScript, anything that appears. Gotchas: you still need a transition on the element (for example .transition-all .duration-300); these utilities animate the entry only, for the exit you also need .transition-discrete and a closed-state style (see the dialog demo). More: MDN: @starting-style.

    ClassCSS
    .starting-opacity-0@starting-style { opacity: 0 }
    .starting-scale-95@starting-style { scale: 0.95 }
    .starting-translate-y-2@starting-style { translate: 0 0.5rem }
    .starting-translate-y-n2@starting-style { translate: 0 -0.5rem }
    .starting-translate-x-full@starting-style { translate: 100% 0 }

    Transition behavior

    .transition-discrete allows transitions on discrete properties like display and overlay, so exit animations can finish before the element is hidden. What: normally display: none flips instantly, which cuts every exit animation. With allow-discrete the flip is delayed until the other transitions have finished (and for the top layer, overlay keeps the element there until then). Gotcha: list display and (for popover, dialog) overlay in the transition property, because the shorthand transition: all does not animate them unless behavior is set. More: MDN: transition-behavior.

    ClassCSS
    .transition-normaltransition-behavior: normal
    .transition-discretetransition-behavior: allow-discrete

    Interpolate size & details

    .interpolate-size-keywords lets height: auto (and other size keywords) be animated; it is inherited, so set it on a parent or on :root. .details-animate animates the open/close of a <details> element via ::details-content. When: accordions, expanding cards, collapsible sidebars: anything that grows to its content size. Gotchas: without the opt-in a transition to or from auto jumps. calc-size(auto, size) is the per-value alternative: it makes a single declaration animatable without the inherited property, and allows maths on the intrinsic size such as calc-size(auto, size + 2rem). More: MDN: interpolate-size, MDN: calc-size().

    ClassCSS
    .interpolate-size-numericinterpolate-size: numeric-only
    .interpolate-size-keywordsinterpolate-size: allow-keywords
    .details-animate::details-content { block-size: 0 → auto } (300ms)

    interpolate-size-keywords vs calc-size(): animate height to auto (hover or focus the cards)

    interpolate-size: allow-keywords

    The box grows from a fixed height to height: auto. The property is inherited, so one class on a parent opts in the whole subtree.

    calc-size(auto, size)

    Same effect with no opt-in at all: the keyword is wrapped in calc-size() in the hover rule only.

/* or per value */

    What is OmniaCSS?

    OmniaCSS generates utility classes from SCSS source files. Each class does one thing, so you compose layouts directly in your markup without writing custom CSS for every component.
