    Migreren / Migrate

    Overstappen van Tailwind CSS naar OmniaCSS en je bestaande klassenamen houden. Switch a Laravel, Vue or React project from Tailwind CSS to OmniaCSS in three steps: your markup stays exactly as it is.

    How it works @birdycom/omniacss-migrate

    A compat layer resolves Tailwind-style class names on demand and emits CSS that only uses OmniaCSS tokens.

    • A PostCSS plugin and a Vite plugin scan your Blade, Vue, JSX/TSX and HTML files and emit CSS for the classes they find (variants like hover:, md:, dark:, group-hover:, arbitrary values w-[37px], opacity modifiers bg-red-500/50, negatives and ! included).
    • Colors map to the nearest Omnia palette token (OKLCH): bg-red-500 becomes var(--color-red-50). No other colors are ever emitted.
    • The entry @import "@birdycom/omniacss-migrate" (what setup --write writes, so no Tailwind name is left), or the Tailwind forms @import "tailwindcss" and @tailwind base|components|utilities, in your CSS are replaced by Omnia core plus the compat output; @apply and @theme keep working.
    • Breakpoints follow OmniaCSS (sm 36rem, md 50rem, lg 64rem); shadows reuse the Omnia shadow values; spacing keeps the familiar 0.25rem step.

    Laravel in 3 steps

    1. Check coverage and preview the switch

    1
2
    npx @birdycom/omniacss-migrate scan .      # % of your class occurrences that are supported
npx @birdycom/omniacss-migrate setup .     # dry run: shows every file it would change

    2. Apply it

    1
2
3
    npx @birdycom/omniacss-migrate setup . --write
npm uninstall tailwindcss @tailwindcss/vite @tailwindcss/postcss
npm install -D @birdycom/omniacss-migrate

    Or by hand, in vite.config.js:

    1
2
3
4
    import omniaMigrate from "@birdycom/omniacss-migrate/vite";
export default defineConfig({
  plugins: [laravel({ input: ["resources/css/app.css", "resources/js/app.js"] }), omniaMigrate()],
});

    3. Build

    1
    npm run dev

    Your app.css does not change. Without Vite, use the PostCSS plugin:

    1
2
3
    // postcss.config.js
import omniaMigrate from "@birdycom/omniacss-migrate/postcss";
export default { plugins: [omniaMigrate({ content: ["resources/views/**/*.blade.php", "resources/js/**/*.{vue,tsx,jsx,js}"] })] };

    Your theme and tailwind.config

    theme.extend.colors, fontFamily, borderRadius, spacing, screens, darkMode and @theme blocks are read automatically. setup --write copies the config theme into your CSS as an @theme block, with literal colors mapped to Omnia tokens (use --keep-brand-colors to keep them as written).

    1
2
3
4
    @theme {
  --color-brand-500: var(--color-vividblue-80);   /* was #3b82f6 */
}
@custom-variant dark (&:where(.dark, .dark *));

    Optional: native OmniaCSS class names

    Rewrite your markup to real Omnia classes where the CSS is identical. Dry run by default.

    1
2
    npx @birdycom/omniacss-migrate codemod resources           # report only
npx @birdycom/omniacss-migrate codemod resources --write   # apply

    Classes without a 1:1 native equivalent are left alone and listed; they keep working through the compat layer. The codemod writes omniacss-migrate.manifest.json so a native p-1 (Omnia, 1rem) is never mixed up with a Tailwind-style p-1 (0.25rem). Run it over the whole project.

    From Bootstrap 3, 4 or 5

    Rewrite a Bootstrap site to OmniaCSS utilities and OmniaUI components. Works on HTML, PHP, Blade, Twig and other templates; template code inside class attributes is left untouched. Dry run by default.

    1
2
3
    npx @birdycom/omniacss-migrate bootstrap scan .              # report only
npx @birdycom/omniacss-migrate bootstrap codemod . --write   # apply
npx omniacss build -o css/omnia.css                          # OmniaCSS for exactly the classes you use
    BootstrapBecomes
    Utilities: mt-3, d-md-none, justify-content-between, text-muted, fw-bold, w-100 …The OmniaCSS class with the same CSS, found by its declarations: mt-1 (both 1rem), md:d-none, justify-between, text-twilightblue-10, font-bold, w-full. Theme colors map to the nearest Omnia token.
    Components: btn, card, alert, badge, form-control, table, breadcrumb, pagination, progress, panel …OmniaUI: oc-btn, oc-card, oc-alert--danger, oc-input (oc-select on a select), oc-table--striped …
    Grid: container, row, col-md-6, offset-*, g-3, row-cols-*Kept, with a generated bootstrap-compat.css for exactly the grid classes in use (OmniaCSS breakpoints, a few KB)
    Utilities without an OmniaCSS twin (border 1px, z-1, mt-n1)Kept, with their exact CSS in the same compat stylesheet
    JavaScript components: modal, dropdown, collapse, carousel, navbar, tabs, offcanvas, toast; icon fontsReported with the native way: <dialog> + commandfor, popover, <details>, scroll snap with .scroll-buttons, OmniaUI tabs
    The Bootstrap <link>Replaced by omnia.css, the OmniaUI CSS and bootstrap-compat.css, in the same asset folder

    The report also lists classes your JavaScript toggles (classList.add('btn-primary')) that the markup now spells differently, and Bootstrap 3 classes in a Bootstrap 5 site, split into "your own CSS still styles it" and "safe to delete". The version is detected from package.json, the <link> URL, a local bootstrap.css header or the markup; override it with --bs 3. With --breakpoints exact responsive classes keep Bootstrap's pixel breakpoints (min-[48rem]:d-none) instead of the nearest OmniaCSS breakpoint.

    CLI reference

    CommandWhat it does
    scan <dir>Coverage report: supported share and the list of unsupported classes
    setup <project> [--write]Plan or apply: package.json, vite/postcss config, CSS theme
    codemod <dir> [--write]Rewrite to native Omnia class names where 1:1
    build [-c glob] [-o file]Write the CSS once, without Vite or PostCSS
    css "<class>"Print the CSS for one class
    bootstrap scan <dir>Bootstrap report: what converts, what stays, what needs a hand
    bootstrap codemod <dir> [--write]Rewrite Bootstrap classes, swap the stylesheet, write bootstrap-compat.css

    The same commands are available as omniacss migrate scan . in the main CLI.

    Known gaps

    • Plugin classes other than tailwindcss-animate (typography, forms, Iconify icons) are not generated.
    • Custom keyframes in tailwind.config are not carried over; add them to your CSS.
    • Class names built at runtime from fragments cannot be scanned: use the safelist option.
    • Breakpoints, shadows and nearest-palette colors differ slightly from the original by design: check the result visually.
