    Performance & accessibility

    _interactivity.scss 0 KB JavaScriptNewest CSSv0.4.0

    will-change hints and reading order for keyboard and screen reader users. All interactivity utilities.

    Will Change

    In plain words: will-change is a note to the browser: "this element is going to move (or fade) soon". The browser then gets the element ready in advance, so the movement starts without a small hitch. You never see the class itself: the page looks exactly the same with or without it.

    Use it only when a movement visibly stutters at its start, for example a large panel that slides in. Do not use it everywhere "to be safe": every element with this note costs memory, and a page full of them gets slower, not faster. More: MDN: will-change.

    ClassCSS Output
    .will-change-autowill-change: auto
    .will-change-scrollwill-change: scroll-position
    .will-change-contentswill-change: contents
    .will-change-transformwill-change: transform
    .will-change-opacitywill-change: opacity

    A hint for the browser only - nothing changes visually. Use it sparingly, on elements that are about to animate.

    You see no difference, and that is correct. The second box was prepared before your mouse arrived; on a small box like this the gain is too small to notice. The class exists for heavy movements on slow devices.

    Reading Flow

    In plain words: somebody who does not use a mouse walks through a page with the Tab key: every press goes to the next button or link. The browser follows the order in which the buttons are written in the HTML. With CSS you can show buttons in another order than they are written (for example with .flex-row-reverse or .order-*). Then Tab jumps back and forth across the screen, which is confusing. reading-flow tells the browser: follow the order people see.

    Gotcha: browsers without support keep following the HTML, so write the HTML in a sensible order anyway and see reading-flow as an extra. More: MDN: reading-flow.

    ClassCSS
    .reading-flow-normalreading-flow: normal
    .reading-flow-flex-visualreading-flow: flex-visual
    .reading-flow-flex-flowreading-flow: flex-flow
    .reading-flow-grid-rowsreading-flow: grid-rows
    .reading-flow-grid-columnsreading-flow: grid-columns
    .reading-flow-grid-orderreading-flow: grid-order
    .reading-flow-source-orderreading-flow: source-order

    The example: both rows hold the same three buttons. In the HTML they are written as Save, Cancel, Help, but CSS shows them the other way round. The small number under each button is the place it has for the Tab key. Read the numbers from left to right: in the first row they run 3, 2, 1 (backwards), in the second row 1, 2, 3 (as you read). Try it with the real keyboard: click Start here in a row and press Tab three times. The demo uses no JavaScript.

    reading-flow: Tab follows the order you see (Chrome 137+)

The grid values (.reading-flow-grid-rows, -grid-columns, -grid-order) work the same way for items that a grid places in another order than the HTML; .reading-flow-normal and .reading-flow-source-order go back to the HTML order.
