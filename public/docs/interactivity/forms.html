    Accent and caret color, appearance, color scheme, resizable boxes, auto-growing fields and the customizable select. All interactivity utilities.

    Accent Color, Appearance, Caret & Color Scheme

    What: accent-color tints native checkboxes, radios, range and progress in one declaration; appearance removes or restores native styling; caret-color colors the text cursor; color-scheme tells the browser which scheme the element supports so it can render native widgets, scrollbars and default colors to match. Gotchas: accent-color picks a readable contrast color itself, so test light and dark; appearance: none removes the focus ring and the check mark, and you must rebuild both. More: MDN: accent-color.

    Accent color is the color the browser uses for the filled part of its own controls: the tick of a checkbox, the dot of a radio button, the filled part of a slider and a progress bar. Each row below holds the same four controls; only the class on the row differs. Opera draws its own form controls and ignores accent-color; Chrome, Edge, Firefox and Safari follow it.

    Resize

    What: lets the user drag the corner of an element to resize it. When: textareas (vertical only is the common choice) and panels. Gotcha: it only works when overflow is not visible, and it is a pointer feature: keyboard users cannot resize, so do not hide content behind it. More: MDN: resize.

    ClassCSS Output
    .resize-noneresize: none
    .resizeresize: both
    .resize-xresize: horizontal
    .resize-yresize: vertical

    Field Sizing

    Let <textarea>, <input> and <select> grow and shrink with their content — no JavaScript auto-resize needed. Combine with a min-*/max-* size to keep the field in bounds. Gotcha: a field with field-sizing: content has no intrinsic width of its own (about one character when empty), so set a min-inline-size as well. More: MDN: field-sizing.

    ClassCSS
    .field-sizing-contentfield-sizing: content
    .field-sizing-fixedfield-sizing: fixed

    .field-sizing-fixed is the normal behaviour (a field keeps its own size whatever you type), so it needs no demo: use it to switch a field back inside a form that has .field-sizing-content.

    field-sizing-content: the field grows while you type

    .field-sizing-content
    Type in both fields: each one grows and shrinks with its text.

    Customizable Select

    .appearance-base-select opts a <select> (and its ::picker(select) dropdown) into the new fully stylable rendering, so options can contain icons and rich HTML. Gotchas: only Chromium renders it today, other browsers show a normal select (a good fallback); the option content must stay accessible text, and you style the open list through ::picker(select). More: MDN: appearance.

    ClassCSS
    .appearance-base-selectappearance: base-select (select and ::picker(select))

    Below: a status select where every option has a colored dot, a name and a short explanation, the open list has rounded corners and a shadow, and the chosen option shows a check mark. All of it is one <select>: keyboard, screen reader and form submit work as always. In a browser without support you see the same options as a plain list.

    appearance-base-select (Chrome 135+; other browsers show a normal select)

    Not in this browser yet. Your browser does not support appearance: base-select: you see a normal select, and every option shows its name and explanation as plain text.
    .appearance-base-select
    Open the select: every option has a colored dot, a name and a short explanation, and the chosen one gets a check mark.
