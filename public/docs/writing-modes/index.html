    Writing Modes & Logical Properties

    CSS class _writing_modes.scss writing-modes/index.html 0 KB JavaScriptBaselinev0.3.0

    Control the direction in which text flows (writing-mode, direction) and use logical inset and sizing utilities that follow that flow. In a right-to-left page .start-0 sticks to the right edge automatically. See MDN: Logical properties.

    Writing mode

    Horizontal or vertical text flow. The older .writingmode-* classes from _text.scss stay available. What: writing-mode sets the direction in which lines are laid out and in which blocks stack; everything that is "logical" (inline-size, margin-inline, inset-inline-start) follows it. When: vertical labels in tables and charts, East Asian typography, sideways rotated headings without transform. Gotcha: sideways-* is newer than vertical-*, and a vertical box needs an explicit block size to avoid collapsing. More: MDN: writing-mode.

    ClassCSS
    .write-horizontalwriting-mode: horizontal-tb
    .write-vertical-rlwriting-mode: vertical-rl
    .write-vertical-lrwriting-mode: vertical-lr
    .write-sideways-rlwriting-mode: sideways-rl
    .write-sideways-lrwriting-mode: sideways-lr

    The same two lines of text in each card; only the writing mode changes. Follow the direction in which the lines run and where the second line goes.

    write-horizontal, write-vertical-rl, write-sideways-lr

    .write-horizontal
    The default: lines run left to right, new lines go down.
    Order 1 shippedCustomer 1, Company 1
    .write-vertical-rl
    Lines run top to bottom, new lines go to the left (Japanese, Chinese).
    Order 1 shippedCustomer 1, Company 1
    .write-sideways-lr
    The whole text is turned a quarter to the left: it reads bottom to top, like a book spine.
    Order 1 shippedCustomer 1, Company 1

    Direction

    Base direction for text and inline layout. Prefer the HTML dir attribute for real content; use these classes for isolated components. Gotcha: the direction property alone does not change the document language; the dir attribute does both and is also read by assistive technology and bidi algorithms. More: MDN: direction.

    ClassCSS
    .dir-ltrdirection: ltr
    .dir-rtldirection: rtl

    Text orientation

    Orientation of characters in a vertical writing mode. When: mixed keeps Latin text sideways while CJK stays upright; upright stacks Latin letters upright, useful for short codes and abbreviations. More: MDN: text-orientation.

    ClassCSS
    .text-orient-mixedtext-orientation: mixed
    .text-orient-uprighttext-orientation: upright
    .text-orient-sidewaystext-orientation: sideways

    All three boxes use .write-vertical-rl; only the text-orient class changes. Compare the Latin letters with the Japanese characters.

    write-vertical-rl + text-orient-*

    .text-orient-mixed
    The default: Japanese characters stay upright, Latin letters and digits lie on their side.
    日本語 Omnia 2026
    .text-orient-upright
    Every character stands upright, also the Latin letters: they stack one under the other.
    日本語 Omnia 2026
    .text-orient-sideways
    Everything lies on its side, also the Japanese characters.
    日本語 Omnia 2026

    Unicode bidi

    Fine-grained control over bidirectional text, e.g. user-generated names inside a sentence in another direction. Gotcha: isolate is the safe default for user-generated content: it prevents a right-to-left name from reordering the punctuation around it. More: MDN: unicode-bidi.

    ClassCSS
    .bidi-normalunicode-bidi: normal
    .bidi-embedunicode-bidi: embed
    .bidi-isolateunicode-bidi: isolate
    .bidi-overrideunicode-bidi: bidi-override
    .bidi-isolate-overrideunicode-bidi: isolate-override
    .bidi-plaintextunicode-bidi: plaintext

    Top row: a customer name in Hebrew (חברה 1, "Company 1") inside an English sentence, as it could come from a form. Watch where ": 3 orders" ends up. Middle row: right-to-left text with and without override. Bottom row: the same Hebrew-first sentence, once with the page direction and once with .bidi-plaintext, which lets the text itself decide its direction. .bidi-embed and .bidi-isolate-override are the older and the combined forms of these and look the same here.

    bidi-normal, bidi-isolate, bidi-override, bidi-plaintext

    .bidi-normal
    The Hebrew name pulls the number and the colon into its own direction: the sentence reads wrong.
    Customer חברה 1: 3 orders
    .bidi-isolate
    The name is kept apart from the text around it: the sentence reads right.
    Customer חברה 1: 3 orders
    .dir-rtl
    Right to left, but Latin letters keep their own order.
    Order 1042
    .dir-rtl .bidi-override
    The direction is forced on every letter: the text is mirrored.
    Order 1042
    .bidi-normal
    The page is left to right, so the Hebrew sentence starts on the left and the ! lands at the end.
    חברה 1 ships today!
    .bidi-plaintext
    The first letter is Hebrew, so the sentence runs right to left and starts on the right.
    חברה 1 ships today!

    Logical inset

    Position utilities that follow the writing direction. Values: auto, 0, 1 (0.25rem), 2 (0.5rem), 4 (1rem), 8 (2rem), full (100%). When: any component that must work in left-to-right and right-to-left layouts (badges, close buttons, drawers): inset-inline-start flips automatically where left would not. More: MDN: inset-inline-start.

    ClassCSS
    .start-{n}inset-inline-start: {value}
    .end-{n}inset-inline-end: {value}
    .inset-inline-{n}inset-inline: {value}
    .inset-block-{n}inset-block: {value}

    Both panels hold a badge with the same classes. Watch on which side the badge ends up when the direction changes.

    .dir-ltr
    The badge has .absolute .start-1 .top-1 and sits top left.
    NewProduct 1Left to right: start is the left side
    .dir-rtl
    The same classes. Only the direction changed, and the badge moved to the top right.
    NewProduct 1Right to left: start is the right side

    Logical sizing

    inline-size is the width in horizontal text and the height in vertical text; block-size is the other axis. Gotcha: mixing physical (width) and logical (block-size) sizes in one component works, but switch the whole component to logical values if you plan to support vertical text. More: MDN: inline-size.

    ClassCSS
    .inline-size-autoinline-size: auto
    .inline-size-fullinline-size: 100%
    .inline-size-fitinline-size: fit-content
    .inline-size-mininline-size: min-content
    .inline-size-maxinline-size: max-content
    .block-size-autoblock-size: auto
    .block-size-fullblock-size: 100%
    .block-size-fitblock-size: fit-content
    .block-size-minblock-size: min-content
    .block-size-maxblock-size: max-content
    .max-inline-size-prosemax-inline-size: 65ch
    .max-inline-size-fullmax-inline-size: 100%

    The colored box is the element; the hatched area is the room it leaves free. The top four tiles are normal horizontal text, where inline size is the width. In the bottom two the box is vertical text: now .inline-size-full fills the height and .block-size-full fills the width.

    inline-size-fit, min, max, full and block-size-full in vertical text

    Hatched = room the box leaves free
    .inline-size-fit
    As wide as the text, but never wider than the room: here the text wraps.
    Free delivery on every order from Company 1 this week
    .inline-size-min
    As narrow as the longest word: every word on its own line.
    Free delivery on every order from Company 1 this week
    .inline-size-max
    As wide as the text on one line, even if that does not fit: it runs out of the box (cut off here).
    Free delivery on every order from Company 1 this week
    .inline-size-full
    The full width of the parent.
    Free delivery on every order from Company 1 this week
    .write-vertical-rl .inline-size-full
    Vertical text: the inline size is now the height, so the box fills it from top to bottom.
    Free delivery
    .write-vertical-rl .block-size-full
    Vertical text: the block size is now the width, so the box fills it from left to right.
    Free delivery
