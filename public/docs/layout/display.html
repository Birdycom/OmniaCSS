    Display

    _display.scss 0 KB JavaScriptBaselinev0.2.0

    Control the display box type of an element using .block, .inline, .none, and more.

    What it does: display decides how an element takes part in layout: as a full-width block, as a flowing inline piece of text, as an inline-block (flows like text, sizes like a box), or not at all (none). When to use: switch an element between these roles, hide things responsibly, or clear floats with flow-root. Gotchas: .none removes the element from the accessibility tree and layout (use .invisible to keep its space); width, height and vertical margins are ignored on inline elements; and contents removes the box but keeps the children, which has had accessibility bugs on buttons and tables. Flex and grid have their own pages. See MDN: display.

    block, inline-block and inline

    Each card holds the same line of text with two colored boxes in it; only the display class on the boxes changes. Look at where the boxes go and what their padding does to the lines of text around them.

    block, inline-block, inline

    .block
    Each box starts on a new line and fills the full width.
    Text before Box 1Box 2 text after the boxes.
    .inline-block
    The boxes stay in the line of text. Their padding pushes the lines apart, and width and height work.
    Text before Box 1 Box 2 text after the boxes.
    .inline
    The boxes flow like words and can wrap. Vertical padding overlaps the lines; width and height are ignored.
    Text before Box 1 Box 2 with longer text text after the boxes.

    Why flow-root

    A floated child takes no height, so a parent with a border collapses around it (left). .flow-root makes the parent contain its floats (right) without clearfix hacks.

    flow-root contains floats

    no flow-root
    The float takes no height, so the frame collapses.
    float
    .flow-root
    The frame grows around the float.
